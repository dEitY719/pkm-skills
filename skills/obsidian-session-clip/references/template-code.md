# 본문 골격 — `session_type: code`

세션 중 커밋이 1개 이상 있었거나 PR 을 만들었을 때 쓴다. 섹션 제목과 순서는
`dEitY719/obsidian-para` PR #5 / #29 의 PR 본문 구조를 그대로 따른다 — 이미
검증된 서술 골격이고, 사용자가 읽는 형식이 PR 과 일관된다.

**섹션 제목과 순서를 바꾸지 않는다.** `/ingest` 가 이 골격을 전제로 읽는다.
해당 없는 섹션은 지우지 말고 `- 없음` 한 줄을 넣는다.


## 채우기 규칙

- **transcript 를 덤프하지 않는다.** 이 노트는 요약본이지 로그가 아니다.
- `## 변경사항` 은 `git diff --stat` 을 그대로 옮기지 말고 파일별 의도를 쓴다.
  통계 원문은 `## 관련` 에 둔다.
- `## 설계 근거` 가 이 노트의 존재 이유다. 여기가 비면 클립할 가치가 없다.
- `## 메모` 3개 하위 섹션은 **모두** 채운다 (F-5). 하나라도 비면
  `lib/verify-clip.sh` 가 FAIL 한다.
- 대화에서 언급된 `#N` 은 전부 `## 관련` 의 이슈/PR 줄에 모은다 (F-6).
- 커밋이 없는데 이 템플릿을 골랐다면 판별이 틀린 것이다 —
  `template-research.md` 로 간다.
